4.1 Optimization Problems & the Greedy Strategy

An optimization problem asks for a feasible solution that maximises (or minimises) some objective function under a set of constraints. A greedy algorithm builds the solution one piece at a time, at every step taking the choice that looks locally best, with the hope that the resulting sequence of locally optimal choices yields a globally optimal solution.

Elements of the greedy strategy

  1. Greedy-choice property — a globally optimal solution can be constructed by making a locally optimal (greedy) choice at every step.
  2. Optimal substructure — an optimal solution to the problem contains within it optimal solutions to sub-problems.
  3. Feasibility check — after each greedy choice, the partial solution must remain feasible (satisfies constraints).

When does greedy give the optimum? When the problem has the two properties above. Examples that satisfy them: Fractional Knapsack, MST (Kruskal/Prim), Single-source shortest path with non-negative weights (Dijkstra), Huffman coding. Examples that do NOT: 0/1 Knapsack, Travelling Salesman — these need Dynamic Programming or Backtracking.

General greedy template

Greedy(C): // C is the candidate set S ← ∅ // solution set while C ≠ ∅ and not solution(S): x ← select(C) // pick locally best item C ← C − {x} if feasible(S ∪ {x}): S ← S ∪ {x} return S

4.2 Fractional Knapsack

Given $n$ items, each with weight $w_i$ and value $v_i$, and a knapsack of capacity $W$, choose fractions $x_i\in[0,1]$ to maximise $\sum x_i v_i$ subject to $\sum x_i w_i \le W$.

Greedy choice

Sort items by value-per-weight ratio $v_i/w_i$ in decreasing order. Take items whole until the next one no longer fits; then take a fraction of that item to exactly fill the knapsack.

Algorithm FractionalKnapsack(v[], w[], n, W): for i = 1 to n: r[i] ← v[i]/w[i] sort items by r[] in decreasing order total ← 0; remain ← W for i = 1 to n: if w[i] ≤ remain: x[i] ← 1; total ← total + v[i]; remain ← remain − w[i] else: x[i] ← remain / w[i] total ← total + x[i] * v[i] break return total

Worked example

Items with $(v_i, w_i)$ = (60,10), (100,20), (120,30); $W=50$.

Ratios: 6, 5, 4 → already in decreasing order Take item 1 fully : w=10, v=60 remain=40 Take item 2 fully : w=20, v=100 remain=20 Take item 3: 20/30 : v=120*20/30=80 remain=0 Total value = 60 + 100 + 80 = 240

Analysis

  • Sorting dominates → $O(n\log n)$.
  • Space: $O(n)$ for ratios.
  • Correctness: exchange argument — swapping any fraction of a higher-ratio item out for a lower-ratio item cannot increase total value.
⚠ 0/1 Knapsack: greedy by ratio is NOT optimal because you can't take fractions. Needs DP (Unit 5) or backtracking (Unit 6).

4.3 Job Sequencing with Deadlines

Given $n$ jobs, each with a deadline $d_i$ and profit $p_i$ (each job takes 1 unit of time), schedule them on a single machine to maximise total profit, where a job earns its profit only if it finishes on or before its deadline.

Greedy choice

Sort jobs by profit in decreasing order. Maintain a time-slot array of size $\max(d_i)$. For each job, place it in the latest free slot $\le d_i$. If no free slot exists, discard the job.

Algorithm JobSequencing(jobs[], n): sort jobs by profit in decreasing order D ← max deadline slot[1..D] ← empty profit ← 0 for each job j (in sorted order): for t = min(D, j.deadline) down to 1: if slot[t] is empty: slot[t] ← j; profit += j.profit; break return slot, profit

Worked example

Jobs: J1(p=20,d=2), J2(p=15,d=2), J3(p=10,d=1), J4(p=5,d=3), J5(p=1,d=3).

After sorting by profit → J1, J2, J3, J4, J5 (D = 3) slot: [ _ , _ , _ ] J1 d=2 → slot[2]=J1 : [ _, J1, _ ] J2 d=2 → slot[1]=J2 : [J2, J1, _ ] J3 d=1 → slot[1] busy, slot[0] none → discard J4 d=3 → slot[3]=J4 : [J2, J1, J4] J5 d=3 → all full → discard Schedule = J2, J1, J4 ; Profit = 15+20+5 = 40

Analysis

  • Sort jobs: $O(n\log n)$. Slot scan per job: $O(D)$ → worst total $O(n\cdot D)$ which is $O(n^2)$ since $D\le n$.
  • Using Disjoint-Set Union for slot search reduces it to $O(n\,\alpha(n))\approx O(n)$ after sorting.

4.4 Minimum Spanning Tree (MST)

A spanning tree of a connected weighted graph $G(V,E)$ is a sub-graph that connects all vertices using exactly $|V|-1$ edges and has no cycles. An MST minimises the total edge weight.

4.4.1 Kruskal’s Algorithm

Build the MST by considering edges in increasing order of weight, adding an edge only if it does not form a cycle. Cycle-check uses Union-Find (DSU).

Algorithm Kruskal(G): sort E by weight ascending MakeSet(v) for each v ∈ V T ← ∅ for each edge (u,v) in sorted order: if Find(u) ≠ Find(v): T ← T ∪ {(u,v)} Union(u, v) if |T| = |V|−1: break return T

Worked example

Edges of a 5-vertex graph (a,b,c,d,e):

(a,b)=1 (c,d)=2 (b,c)=3 (a,c)=4 (d,e)=5 (b,e)=6 Sorted already. Pick (a,b)=1 → {a,b} Pick (c,d)=2 → {a,b},{c,d} Pick (b,c)=3 → {a,b,c,d} Skip (a,c)=4 (same set) Pick (d,e)=5 → {a,b,c,d,e} ✓ MST weight = 1+2+3+5 = 11

Analysis

  • Sort edges: $O(E\log E)$.
  • $E$ DSU operations: $O(E\,\alpha(V))\approx O(E)$.
  • Total: $O(E\log E)=O(E\log V)$.

4.4.2 Prim’s Algorithm

Start from an arbitrary vertex; grow the tree one vertex at a time by adding the cheapest edge that connects a vertex inside the tree to a vertex outside it.

Algorithm Prim(G, r): key[v] ← ∞ for all v; key[r] ← 0 parent[v] ← NIL Q ← V // min-priority queue keyed by key[] while Q ≠ ∅: u ← ExtractMin(Q) for each (u,v) ∈ E: if v ∈ Q and w(u,v) < key[v]: key[v] ← w(u,v); parent[v] ← u return {(v, parent[v]) : v ∈ V \ {r}}

Analysis

  • Binary-heap priority queue: $O((V+E)\log V) = O(E\log V)$.
  • Fibonacci heap: $O(E + V\log V)$ — theoretically faster on dense graphs.

4.5 Dijkstra’s Single-Source Shortest Path

Given a directed/undirected graph with non-negative edge weights and a source $s$, compute the shortest-path distance from $s$ to every other vertex.
Algorithm Dijkstra(G, s): dist[v] ← ∞ for all v; dist[s] ← 0 parent[v] ← NIL Q ← V // min-priority queue keyed by dist[] while Q ≠ ∅: u ← ExtractMin(Q) for each (u,v) ∈ E: if dist[u] + w(u,v) < dist[v]: dist[v] ← dist[u] + w(u,v) // RELAX parent[v] ← u return dist, parent

Worked example

Graph with edges from source A: A→B(4), A→C(1), C→B(2), C→D(5), B→D(1).

Init dist=[A:0, B:∞, C:∞, D:∞] Extract A : relax A→B(4) → dist[B]=4 ; A→C(1) → dist[C]=1 Extract C : relax C→B(1+2=3) < 4 → dist[B]=3 ; C→D(1+5=6) → dist[D]=6 Extract B : relax B→D(3+1=4) < 6 → dist[D]=4 Extract D : done Result dist[A,B,C,D] = [0, 3, 1, 4]

Analysis

  • Binary-heap PQ: $O((V+E)\log V)$.
  • Fibonacci heap: $O(E + V\log V)$.
  • Array (no PQ): $O(V^2)$ — better for dense graphs.
⚠ Negative-weight edges break Dijkstra (a vertex can be "finalised" too early). Use Bellman–Ford ($O(VE)$) instead.

4.6 Huffman Coding

A prefix code is a set of binary codewords in which no codeword is a prefix of another. Huffman produces an optimal prefix code that minimises the total bit length $\sum f_i \cdot |c_i|$ for a given symbol-frequency table.

Algorithm

Huffman(C): // C = set of n symbols Q ← C // min-heap by frequency for i = 1 to n-1: z ← new node x ← ExtractMin(Q) y ← ExtractMin(Q) z.left ← x; z.right ← y z.freq ← x.freq + y.freq Insert(Q, z) return ExtractMin(Q) // root of Huffman tree

Codeword of a symbol = path from root to its leaf (0 = left, 1 = right).

Worked example

Frequencies: a=30, b=20, c=25, d=15, e=35. Build:

Sorted d:15, b:20, c:25, a:30, e:35 Merge d+b → 35 queue: c:25, a:30, e:35, 35 Merge c+a → 55 queue: e:35, 35, 55 Merge e+35 → 70 queue: 55, 70 Merge 55+70 → 125 (root) Tree paths: 125 / \ 55 70 / \ / \ c a e 35 / \ d b Codes: c = 00 a = 01 e = 10 d = 110 b = 111 Total bits = 30·2 + 20·3 + 25·2 + 15·3 + 35·2 = 60 + 60 + 50 + 45 + 70 = 285 bits Compare with fixed 3-bit: 125·3 = 375 bits → 24 % saving.

Analysis

  • Each merge: 2 extract-min + 1 insert = $O(\log n)$.
  • $n-1$ merges → $O(n\log n)$ total.
  • Optimality: proof by exchange argument — the two lowest-frequency symbols can always be siblings at the deepest level.
