🧪 Unit 5 — Tricky Variations & Common Mistakes

1. “Pseudo-polynomial” — not real polynomial

0/1 Knapsack is $\Theta(nW)$. If $W=2^{32}$ but the input size $\log W=32$, the algorithm is exponential in input length — hence the term pseudo-polynomial. Mention this when describing Knapsack as “efficient”.

2. MCM — chain length loop, not (i,j) loops

Wrong: iterate i and j independently. Right: iterate chain length L = 2,3,…,n, then set j = i+L−1. Otherwise sub-problems may not be ready when needed.

3. Edit Distance — first row / column

Always initialise dp[0][j]=j and dp[i][0]=i (cost of all inserts/deletes). Forgetting this gives off-by-one errors.

4. Floyd–Warshall — the order of loops matters

k MUST be the outermost loop. Reversing the order (e.g. i outermost) breaks the recurrence because we'd compare against a half-updated table.

5. Greedy vs DP for Knapsack — quick test

Items divisible → Fractional Knapsack → greedy works.
Items indivisible → 0/1 Knapsack → DP required. Examiners give one of the two; read carefully.

6. TSP — the 1→i→… convention

Tour cost includes returning to the start city. Don't forget the +d(i,1) term in the answer. Hamiltonian path (no return) is a different problem.

7. Floyd–Warshall vs Dijkstra-on-every-vertex

Both compute all-pairs shortest paths. F–W is $\Theta(n^3)$ and handles negative weights. Running Dijkstra from each vertex is $\Theta(VE\log V)$ — faster on sparse, non-negative graphs.

8. Recovering the actual solution (not just the optimal value)

Store the choice that achieved each cell’s minimum (e.g. s[i,j]=k in MCM, or a parent pointer in Knapsack). After filling the table, back-track from the answer cell to print the actual subset / parenthesisation.

9. Space optimisation tricks

• Knapsack: keep one row, iterate w from W down to w_i.
• Edit Distance: keep two rows (previous + current).
• Fibonacci-style DP: keep two scalars.

10. Memoization vs Tabulation — when each wins

Memo wins when the state space is sparse and you don’t need every cell (recursive structure naturally prunes). Tab wins when you fill almost every cell and want the speed of a tight loop without function-call overhead.
