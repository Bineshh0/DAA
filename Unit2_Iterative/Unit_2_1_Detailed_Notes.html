2.1 Basic Iterative Algorithms

2.1.1 Greatest Common Divisor (GCD)

The GCD of two non-negative integers $a,b$ (not both zero) is the largest integer that divides both. Euclid's principle: $\gcd(a,b)=\gcd(b,\,a\bmod b)$ with base case $\gcd(a,0)=a$.

Iterative Euclidean algorithm

Algorithm GCD(a, b): while b ≠ 0 do r ← a mod b a ← b b ← r return a

Trace GCD(48, 18):

a=48 b=18 r = 48 mod 18 = 12 → a=18 b=12 a=18 b=12 r = 18 mod 12 = 6 → a=12 b=6 a=12 b=6 r = 12 mod 6 = 0 → a=6 b=0 return 6

Complexity analysis

After two iterations the value of $b$ falls below $a/2$ (a consequence of the Fibonacci-based proof by Lamé). Hence the number of iterations is bounded by $2\log_2(\min(a,b))$.

  • Time: $T(a,b)=O(\log(\min(a,b)))$
  • Space: $O(1)$ — only constant variables.
  • Worst case: $a,b$ are consecutive Fibonacci numbers (slowest reduction).

2.1.2 Fibonacci Number

Fibonacci sequence: $F_0=0,F_1=1,F_n=F_{n-1}+F_{n-2}$ for $n\ge 2$ → $0,1,1,2,3,5,8,13,\dots$

(a) Naive recursive version

Algorithm Fib(n): if n ≤ 1: return n return Fib(n-1) + Fib(n-2)

Recurrence $T(n)=T(n-1)+T(n-2)+O(1) \Rightarrow T(n)=\Theta(\varphi^n)\approx\Theta(1.618^n)$ — exponential. Space $=\Theta(n)$ for the call stack.

(b) Iterative (bottom-up) version

Algorithm FibIter(n): if n ≤ 1: return n a ← 0; b ← 1 for i = 2 to n do c ← a + b a ← b b ← c return b
  • Time: $\Theta(n)$ — a single linear loop.
  • Space: $\Theta(1)$ — only three variables (no array required).
Insight: The iterative version is exponentially faster than the naive recursive one because it eliminates the repeated re-computation of overlapping sub-problems — the same idea that motivates dynamic programming in Unit 5.

2.2 Searching — Sequential (Linear) Search

Sequential search scans the array from left to right comparing each element with the search key, returning the index when found or −1 if absent. Works on any array (sorted or unsorted).
Algorithm SequentialSearch(A[0..n-1], key): for i = 0 to n-1 do if A[i] = key then return i return -1

Analysis

CaseComparisonsComplexity
Best1 — key at index 0$\Omega(1)$
Worst$n$ — key absent / at last index$O(n)$
Average$\approx n/2$ — uniform position$\Theta(n)$

Space: $\Theta(1)$. The strength of sequential search is its simplicity and its independence from data ordering; its weakness is the linear worst-case cost.

2.3 Iterative Sorting Algorithms

All three sorts below are comparison sorts, in-place (auxiliary $O(1)$), and have worst-case time $\Theta(n^2)$.

2.3.1 Bubble Sort

Repeatedly steps through the list, compares adjacent pairs and swaps them if out of order. After pass $i$, the $i$-th largest element "bubbles" into its final position at the end of the array.
Algorithm BubbleSort(A[0..n-1]): for i = 0 to n-2 do swapped ← false for j = 0 to n-2-i do if A[j] > A[j+1] then swap(A[j], A[j+1]) swapped ← true if not swapped then break // already sorted return A

Trace on $(5,1,4,2,8)$:

Pass 1: (1,4,2,5,8) Pass 2: (1,2,4,5,8) Pass 3: no swap → done

Analysis

  • Comparisons: $\sum_{i=0}^{n-2}(n-1-i)=n(n-1)/2$.
  • Best case (already sorted, with the swapped flag) $=\Theta(n)$.
  • Worst / average $=\Theta(n^2)$.
  • Space: $\Theta(1)$. Stable: yes.

2.3.2 Selection Sort

Repeatedly selects the minimum element from the unsorted suffix and swaps it into the next position of the sorted prefix.
Algorithm SelectionSort(A[0..n-1]): for i = 0 to n-2 do min ← i for j = i+1 to n-1 do if A[j] < A[min] then min ← j swap(A[i], A[min]) return A

Trace on $(64,25,12,22,11)$:

i=0 min=11 → (11,25,12,22,64) i=1 min=12 → (11,12,25,22,64) i=2 min=22 → (11,12,22,25,64) i=3 min=25 → (11,12,22,25,64)

Analysis

  • Comparisons: exactly $n(n-1)/2$ regardless of input.
  • Swaps: at most $n-1$ — the fewest among the three sorts (useful when writes are expensive).
  • Time: $\Theta(n^2)$ best / average / worst.
  • Space: $\Theta(1)$. Stable: no (a swap can move an equal-valued element past another).

2.3.3 Insertion Sort

Builds the sorted array one element at a time: each new element is shifted left across the sorted prefix until it lands in its correct position. Mirrors how people sort playing cards.
Algorithm InsertionSort(A[0..n-1]): for i = 1 to n-1 do key ← A[i] j ← i - 1 while j ≥ 0 and A[j] > key do A[j+1] ← A[j] j ← j - 1 A[j+1] ← key return A

Trace on $(5,2,4,6,1,3)$:

i=1 key=2 → (2,5,4,6,1,3) i=2 key=4 → (2,4,5,6,1,3) i=3 key=6 → (2,4,5,6,1,3) i=4 key=1 → (1,2,4,5,6,3) i=5 key=3 → (1,2,3,4,5,6)

Analysis

  • Best (already sorted, inner loop never runs) $=\Theta(n)$.
  • Worst (reverse sorted) $=\Theta(n^2)$ — each new element shifts past every prior one.
  • Average $=\Theta(n^2)$.
  • Space: $\Theta(1)$. Stable: yes.
  • Adaptive: runs in $\Theta(n+d)$ where $d$ = number of inversions, so it is very fast on nearly-sorted data.
