3.0 The Divide-and-Conquer Paradigm

A Divide-and-Conquer algorithm solves a problem by:
  1. Divide the problem into smaller sub-problems of the same type.
  2. Conquer each sub-problem recursively. Sub-problems small enough are solved directly (base case).
  3. Combine the sub-problem solutions into a solution for the original problem.
This yields a recurrence $T(n)=aT(n/b)+f(n)$ usually solved with the Master Theorem (Unit 1).

3.1 Searching

3.1.1 Binary Search

Pre-condition: the array $A$ is sorted. Compare the key with the middle element; if equal return; if smaller recurse on the left half; if larger recurse on the right half.
Algorithm BinarySearch(A, low, high, key): if low > high: return -1 mid ← (low + high) / 2 if A[mid] = key: return mid if key < A[mid]: return BinarySearch(A, low, mid-1, key) else: return BinarySearch(A, mid+1, high, key)

Trace searching key = 23 in $A=[2,5,8,12,16,23,38,56,72,91]$:

low=0 high=9 mid=4 A[4]=16 < 23 → search right low=5 high=9 mid=7 A[7]=56 > 23 → search left low=5 high=6 mid=5 A[5]=23 ✓ return 5

Analysis

  • Recurrence: $T(n)=T(n/2)+\Theta(1)$ → Master Case 2 → $T(n)=\Theta(\log n)$.
  • Best $\Omega(1)$ (key at middle), worst $O(\log n)$.
  • Space: recursive $\Theta(\log n)$ stack; iterative $\Theta(1)$.

3.1.2 Min-Max Finding

Find both the minimum and maximum of an array in fewer comparisons than $2(n-1)$ of the naive approach.

Divide-and-Conquer MinMax

Algorithm MinMax(A, low, high): if low = high: return (A[low], A[low]) if high = low + 1: if A[low] < A[high]: return (A[low], A[high]) else: return (A[high], A[low]) mid ← (low+high)/2 (min1,max1) ← MinMax(A, low, mid) (min2,max2) ← MinMax(A, mid+1, high) return (min(min1,min2), max(max1,max2))

Analysis

Recurrence (comparisons): $T(n)=2T(n/2)+2,\ T(2)=1$. Solving: $T(n)=\lceil 3n/2\rceil-2$, beating the naive $2n-2$ by 25 %.

Time $=\Theta(n)$ (Master Case 1: $n^{\log_2 2}=n$ vs $f=2$ → Case 1). Space $=\Theta(\log n)$ stack.

3.2 Sorting

3.2.1 Merge Sort

Divide the array into two halves, recursively sort each half, then merge the two sorted halves into one sorted output using a linear scan with an auxiliary array.
Algorithm MergeSort(A, l, r): if l < r: m ← (l+r)/2 MergeSort(A, l, m) MergeSort(A, m+1, r) Merge(A, l, m, r) Merge(A, l, m, r): // l..m and m+1..r are already sorted copy A[l..m] → L; A[m+1..r] → R i ← j ← 0; k ← l while i < |L| and j < |R|: if L[i] ≤ R[j]: A[k] ← L[i]; i++ else: A[k] ← R[j]; j++ k++ copy any remaining L or R into A

Analysis

  • Recurrence $T(n)=2T(n/2)+\Theta(n)$ → Master Case 2 → $T(n)=\Theta(n\log n)$ in best, average, AND worst case.
  • Space $=\Theta(n)$ (auxiliary L,R). Stable: yes. In-place: no.

3.2.2 Quick Sort

Pick a pivot; partition the array so that everything ≤ pivot lies on its left and everything > pivot on its right; recurse on the two sides. The merge step is trivial because partitioning leaves the array in place.
Algorithm QuickSort(A, l, r): if l < r: p ← Partition(A, l, r) QuickSort(A, l, p-1) QuickSort(A, p+1, r) Partition(A, l, r): // Lomuto scheme, pivot = A[r] x ← A[r]; i ← l-1 for j = l to r-1: if A[j] ≤ x: i++; swap A[i],A[j] swap A[i+1], A[r] return i+1

Trace on $(15,7,5,2,13,4,25)$ (pivot = last):

Initial: 15 7 5 2 13 4 | 25 Partition by 25 → pivot lands at index 6 → (15,7,5,2,13,4) | 25 Next pivot 4: → (2) (4) (15,7,5,13) Next pivot 13: → (7,5) (13) (15) Next pivot 5: → (2,4,5,7,13,15,25)

Analysis

Space $=\Theta(\log n)$ average, $\Theta(n)$ worst (recursion depth). In-place: yes. Stable: no.

3.2.3 Randomized Quick Sort

Before partitioning, swap $A[r]$ with $A[\text{random}(l,r)]$. The pivot is now uniformly random, so the worst case becomes exponentially unlikely rather than triggered by sorted input.
RandomizedPartition(A, l, r): i ← random(l, r) swap A[i], A[r] return Partition(A, l, r)

Expected time $=\Theta(n\log n)$ on every input. Worst-case is still $\Theta(n^2)$ but only with probability $O(1/n!)$.

3.2.4 Heap Sort

A (max-)heap is a complete binary tree where every parent ≥ its children. Stored in an array: parent($i$) $=\lfloor i/2\rfloor$, left $=2i$, right $=2i+1$.

Heapify (sink an element)

MaxHeapify(A, i, n): l ← 2i; r ← 2i+1; largest ← i if l ≤ n and A[l] > A[largest]: largest ← l if r ≤ n and A[r] > A[largest]: largest ← r if largest ≠ i: swap A[i], A[largest] MaxHeapify(A, largest, n)

Heapify runs in $O(\log n)$ — the height of the heap.

Build-Heap

BuildMaxHeap(A, n): for i = ⌊n/2⌋ down to 1: MaxHeapify(A, i, n)

Although the naive bound is $O(n\log n)$, a tighter sum over heights gives $T(n)=O(n)$ — provable from $\sum_{h=0}^{\log n} n/2^{h+1}\cdot h = O(n)$.

Heap Sort

HeapSort(A, n): BuildMaxHeap(A, n) // O(n) for i = n down to 2: swap A[1], A[i] // move max to end MaxHeapify(A, 1, i-1) // restore heap on size i-1

Trace Build-Heap on $(4,10,3,5,1)$ → start at i=2: heapify gives $(4,10,3,5,1)$ → $(4,10,3,5,1)$; i=1 sinks 4 → $(10,5,3,4,1)$. Now repeatedly extract max.

Analysis

  • Build-heap: $\Theta(n)$. Each extract-max: $\Theta(\log n)$, repeated $n-1$ times.
  • Total time $=\Theta(n\log n)$ in best, average, AND worst case.
  • Space $=\Theta(1)$ in-place. Stable: no.

3.3 Order Statistics — Selection Problem

The $i$-th order statistic of an $n$-element set is the $i$-th smallest element. Special cases: minimum ($i=1$), maximum ($i=n$), median ($i=\lceil n/2\rceil$).

3.3.1 Selection in Expected Linear Time (RANDOMIZED-SELECT)

RandomizedSelect(A, l, r, i): if l = r: return A[l] q ← RandomizedPartition(A, l, r) k ← q - l + 1 // rank of pivot within A[l..r] if i = k: return A[q] if i < k: return RandomizedSelect(A, l, q-1, i) else: return RandomizedSelect(A, q+1, r, i-k)

Expected recurrence $T(n)=T(\max(k,n-k))+\Theta(n)$ with $k$ uniform → solves to $\Theta(n)$. Worst case still $\Theta(n^2)$.

3.3.2 Selection in Worst-Case Linear Time (Median-of-Medians, BFPRT)

To guarantee $O(n)$ even in the worst case, choose a pivot smart enough to drop at least 30 % of elements on each side.

Select(A, i): 1. Divide A into ⌈n/5⌉ groups of ≤ 5 elements. 2. Sort each group; let M = list of the medians. 3. x ← Select(M, ⌈|M|/2⌉) // median of medians 4. Partition A around x → k elements ≤ x on left. 5. if i = k: return x if i < k: return Select(left, i) else: return Select(right, i-k)

Why it is linear

The chosen pivot $x$ is guaranteed to be greater than at least $3\lceil n/10\rceil$ elements and smaller than at least $3\lceil n/10\rceil$ elements. Hence each recursive call shrinks the array to at most $7n/10$.

Recurrence: $T(n)\le T(n/5)+T(7n/10)+\Theta(n)$. Since $1/5+7/10=9/10<1$, expanding gives a geometric series → $T(n)=\Theta(n)$.
