Algorithm Properties & RAM Model

A. Elementary Properties of an Algorithm

  • Finiteness: The algorithm must terminate after a finite number of steps.
  • Definiteness: Each step must be precisely defined, unambiguous, and clear.
  • Input: It takes zero or more inputs provided externally.
  • Output: It must produce at least one output corresponding to the input.
  • Effectiveness: Every operation must be basic enough to be executed exactly and in finite time.

B. RAM Model Analysis

The Random Access Machine (RAM) model is a theoretical abstraction used to analyze the execution time of an algorithm independently of the specific hardware it runs on.

Rules of RAM Model:
1. Every simple operation (+, -, *, =, if, call) takes exactly 1 time step.
2. Memory access (read/write) takes exactly 1 time step.
3. Loops and function calls are composed of these simple operations. 
sum = 0           // Cost: 1, Executed: 1 time
for i=1 to n:     // Cost: 1, Executed: n+1 times (includes exit check)
    sum = sum + i // Cost: 2 (addition+assignment), Executed: n times
return sum        // Cost: 1, Executed: 1 time

Total Time \( T(n) = 1 + (n+1) + 2n + 1 = 3n + 3 \). Thus, \( T(n) = O(n) \).

Q210 marks
Divide and Conquer & Randomized Quick Sort

A. Divide and Conquer Paradigm

This strategy solves a problem by breaking it into smaller sub-problems of the same type, solving them independently (often recursively), and then combining their results. Example: Merge Sort divides an array in half until single elements remain, then merges the sorted halves.

B. Randomized Quick Sort

Algorithm RandPartition(A, p, r):
  i = Random(p, r)
  swap(A[i], A[r])
  return Partition(A, p, r) // Standard partition using A[r] as pivot

Algorithm RandQuickSort(A, p, r):
  if p < r:
      q = RandPartition(A, p, r)
      RandQuickSort(A, p, q-1)
      RandQuickSort(A, q+1, r)

Time Complexity: By randomly selecting the pivot, the probability of consistently picking the worst pivot (producing \( 0 \) and \( n-1 \) splits) becomes astronomically low. The expected split is sufficiently balanced (like \( 1/4 \) and \( 3/4 \)). This yields an expected time complexity of \( O(n \log n) \) across all possible inputs, eliminating the \( O(n^2) \) worst-case scenario dependent on initial data order.

Q310 marks
Dynamic Programming & 0/1 Knapsack

A. Dynamic Programming vs Recursion

Dynamic Programming solves optimization problems with overlapping subproblems by storing their results in a table (tabulation or memoization) to avoid redundant calculations. Recursion simply calls itself, and without memoization, it will recompute identical subproblems repeatedly, often leading to exponential \( O(2^n) \) time complexity.

B. 0/1 Knapsack using DP

Let \( V[i, w] \) be the maximum value achievable using the first \( i \) items with a knapsack capacity of \( w \).

\( V[i, w] = V[i-1, w] \) if \( wt[i] > w \) (Item is too heavy, skip it).

\( V[i, w] = \max(V[i-1, w], V[i-1, w-wt[i]] + profit[i]) \) if \( wt[i] \leq w \).

Algorithm 01Knapsack(wt[], profit[], W, n):
  Let K[0..n, 0..W] be a matrix initialized to 0
  for i = 1 to n:
      for w = 1 to W:
          if wt[i-1] <= w:
              K[i][w] = max(profit[i-1] + K[i-1][w-wt[i-1]], K[i-1][w])
          else:
              K[i][w] = K[i-1][w]
  return K[n][W]

Time Complexity: \( O(nW) \) where \( n \) is number of items and \( W \) is knapsack capacity. (Note: This is pseudo-polynomial).

Recursion Tree Method: \( T(n) = 2T(n/2) + 1 \)

1. Draw the tree where the root cost is \( 1 \).

2. The root has 2 children, each with cost \( 1 \). Total cost at depth 1 = \( 2 \).

3. Depth 2 has 4 nodes, each with cost \( 1 \). Total cost at depth 2 = \( 4 \).

4. The cost at depth \( k \) is \( 2^k \).

5. The tree stops when \( n/2^k = 1 \implies k = \log_2 n \).

6. Total cost is the sum of costs at all levels: \( 1 + 2 + 4 + ... + 2^{\log_2 n} \).

This is a geometric series sum: \( \sum_{i=0}^{\log_2 n} 2^i = 2^{\log_2 n + 1} - 1 = 2 \cdot 2^{\log_2 n} - 1 = 2n - 1 \).

Complexity: \( O(n) \)
Q55 marks
Maximum Element of Array & Complexity
Algorithm FindMax(A, n):
  max_val = A[0]
  for i = 1 to n-1:
      if A[i] > max_val:
          max_val = A[i]
  return max_val

Time Complexity: The loop runs exactly \( n-1 \) times. The basic operation is the comparison A[i] > max_val. Therefore, the time complexity is strictly \( O(n) \).

Q65 marks
Bubble Sort Algorithm
Algorithm BubbleSort(A):
  n = length(A)
  for i = 0 to n-1:
      for j = 0 to n-i-2:
          if A[j] > A[j+1]:
              swap(A[j], A[j+1])

Time Complexity: The outer loop runs \( n \) times, inner loop runs \( n-i \) times. Total comparisons = \( n(n-1)/2 \). Complexity is \( O(n^2) \) in both worst and average cases. (Can be optimized to \( O(n) \) best case with a 'swapped' flag).

Optimization Problem & Greedy Strategy

An Optimization Problem is a problem where the goal is to find the "best" solution (maximum profit, shortest path, minimum cost) from all feasible solutions.

The Greedy Strategy solves optimization problems by making a sequence of choices. At each step, it makes the choice that looks locally the best at that moment, without looking ahead or revising previous choices. It works well for problems with the Greedy Choice Property and Optimal Substructure (like Kruskal's MST).

Job Sequencing with Deadlines
Algorithm JobSequencing(Jobs):
  Sort Jobs in descending order of Profit
  max_deadline = find max deadline among all jobs
  slots = array of size max_deadline initialized to empty
  
  for each job in Jobs:
      Find a free slot from min(job.deadline, max_deadline) down to 1
      if free slot found:
          slots[found_slot] = job
  return slots

Time Complexity: Sorting takes \( O(n \log n) \). The nested loop for slot finding takes \( O(n^2) \) worst-case. Overall complexity is \( O(n^2) \).

Q95 marks
Memoization Strategy vs DP
  • Memoization: A Top-Down approach. It writes a standard recursive algorithm but saves (caches) the result of each subproblem in a lookup table before returning it. Future recursive calls just fetch the cached value.
  • Tabulation (DP): A Bottom-Up approach. It iteratively builds a table starting from the smallest base cases up to the final answer, avoiding recursion overhead completely.
Q105 marks
Backtracking vs Recursion

Recursion is a coding technique where a function calls itself. Backtracking is an algorithmic methodology that uses recursion to explore a search space. Crucially, backtracking uses a "bounding function" to kill off paths that lead to dead ends. If a partial solution violates the constraints, backtracking immediately abandons it and explores the next branch, whereas pure recursion would mindlessly explore everything.

Q115 marks
P, NP, and NP-Complete
  • P (Polynomial Time): Problems solvable by a deterministic machine in \( O(n^k) \) time. (e.g., MST, Sorting).
  • NP (Non-deterministic Polynomial Time): Problems whose solutions can be verified in polynomial time. (e.g., Sudoku solution check).
  • NP-Complete: A problem X is NP-Complete if X is in NP, and every problem in NP can be reduced to X in polynomial time. They are the hardest problems in NP. (e.g., TSP, SAT).
Q125 marks
Short Notes

(a) NP-Hard Problems and NP Completeness

A problem is NP-Hard if all problems in NP are polynomial-time reducible to it, but it does NOT have to be in NP itself (e.g., the Halting Problem). NP-Complete problems are simply NP-Hard problems that also belong to the class NP.

(b) Problem Reduction

A technique to prove a problem is hard. If we know Problem A is NP-Complete, and we can transform (reduce) Problem A into Problem B in polynomial time, it implies Problem B is at least as hard as A. Thus, B is also NP-Hard. This creates a chain of proofs starting from Cook's Theorem (SAT).
