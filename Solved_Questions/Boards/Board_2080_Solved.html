Recurrence Relation & Substitution Method

A. What is a recurrence relation? How can it be solved?

A recurrence relation is an equation or inequality that describes a function in terms of its value on smaller inputs. It is used heavily to analyze the time complexity of divide-and-conquer algorithms (like Merge Sort). Methods to solve it include:

  • Substitution Method (Guess and prove by mathematical induction)
  • Recursion Tree Method (Visualizing the recursive calls)
  • Master's Theorem (Direct formula for \( T(n) = aT(n/b) + f(n) \))

B. Substitution Method for \( T(n) = 2T(n/2) + 1 \)

Goal: Prove \( T(n) = O(n) \).

Guess: \( T(n) \leq cn - d \) for some constants \( c > 0, d > 0 \).

Inductive Step: Assume the guess holds for \( n/2 \), i.e., \( T(n/2) \leq c(n/2) - d \).

Substitute into the recurrence:

\( T(n) = 2T(n/2) + 1 \)

\( T(n) \leq 2(c(n/2) - d) + 1 \)

\( T(n) \leq cn - 2d + 1 \)

We want \( T(n) \leq cn - d \). This holds if:

\( cn - 2d + 1 \leq cn - d \)

\( -2d + 1 \leq -d \implies d \geq 1 \).

Therefore, with \( d \geq 1 \), the guess holds. Thus, \( T(n) = O(n) \).

DP vs Greedy & Matrix Chain Multiplication

A. Advantages of Dynamic Programming over Greedy Strategy

  • Guaranteed Optimality: DP checks all possible subproblems to make an informed decision, guaranteeing a global optimum. Greedy makes local optimum choices, which sometimes fail globally.
  • Overlapping Subproblems: DP efficiently caches repeated subproblem results (memoization/tabulation), avoiding redundant work that greedy might struggle with in certain tree structures.

B. Matrix Chain Multiplication (2x4, 4x2, 4x5)

Matrices: \( A_1(2 \times 4) \), \( A_2(4 \times 2) \), \( A_3(2 \times 5) \).

Dimensions array \( P = [2, 4, 2, 5] \).

Calculate cost for chain length 2:

\( M[1,2] = A_1 \times A_2 = 2 \times 4 \times 2 = 16 \).

\( M[2,3] = A_2 \times A_3 = 4 \times 2 \times 5 = 40 \).

Calculate cost for chain length 3:

\( M[1,3] = \min \begin{cases} M[1,1] + M[2,3] + P_0 P_1 P_3 = 0 + 40 + (2 \times 4 \times 5) = 40 + 40 = 80 \\ M[1,2] + M[3,3] + P_0 P_2 P_3 = 16 + 0 + (2 \times 2 \times 5) = 16 + 20 = 36 \end{cases} \)

The minimum is 36, which occurs when splitting at \( k=2 \).

Optimal Parenthesization: (A₁A₂)A₃ with minimum cost = 36

Heapify Operation
Heapify is the process of reshaping a binary tree into a Max-Heap or Min-Heap. In a Max-Heap, it ensures that every parent node is greater than or equal to its child nodes. It works by "sifting down" a node that violates the heap property.

Example

If we have tree [4, 10, 3, 5, 1] where 4 violates Max-Heap property. We compare 4 with its children (10 and 3). Max is 10. Swap 4 and 10. Tree becomes [10, 4, 3, 5, 1]. Check children of 4 (5 and 1). Max is 5. Swap 4 and 5. Tree becomes [10, 5, 3, 4, 1].

Algorithm

MAX-HEAPIFY(A, i, n)
  l = 2i       // left child
  r = 2i + 1   // right child
  largest = i
  if l <= n and A[l] > A[largest]
      largest = l
  if r <= n and A[r] > A[largest]
      largest = r
  if largest != i
      swap(A[i], A[largest])
      MAX-HEAPIFY(A, largest, n)

Complexity Analysis

  • Time Complexity: \( O(\log n) \). In the worst case, a node drops all the way to the leaf, taking time proportional to the height of the tree.
  • Space Complexity: \( O(\log n) \) due to the recursion call stack, or \( O(1) \) if implemented iteratively.

RAM Model & Iterative Factorial Analysis

RAM Model (Random Access Machine): A theoretical machine model used to analyze algorithms independent of specific hardware. It assumes each simple instruction (add, multiply, assignment) takes 1 unit of time, and memory access takes 1 unit of time.

Algorithm Factorial(n):
  fact = 1           // 1 cost
  for i = 1 to n     // n+1 comparisons, n increments
      fact = fact * i  // n multiplications, n assignments
  return fact        // 1 cost

Analysis: Total operations \( = 1 + (n+1) + n + 2n + 1 = 4n + 3 \). Time complexity is \( O(n) \).

Insertion Sort Algorithm
INSERTION-SORT(A)
  for j = 2 to A.length
      key = A[j]
      i = j - 1
      while i > 0 and A[i] > key
          A[i + 1] = A[i]
          i = i - 1
      A[i + 1] = key
  • Time Complexity: Best Case \( O(n) \) (already sorted), Worst/Average Case \( O(n^2) \) (reverse sorted).
  • Space Complexity: \( O(1) \) since it sorts in-place.

Minimax Algorithm
function MINIMAX(node, depth, isMaximizingPlayer)
  if depth == 0 or node is terminal
      return heuristic_value_of_node
  
  if isMaximizingPlayer
      bestVal = -INFINITY
      for each child of node
          val = MINIMAX(child, depth - 1, FALSE)
          bestVal = MAX(bestVal, val)
      return bestVal
  else
      bestVal = +INFINITY
      for each child of node
          val = MINIMAX(child, depth - 1, TRUE)
          bestVal = MIN(bestVal, val)
      return bestVal

Complexity: Time: \( O(b^m) \) where b is branching factor and m is maximum depth. Space: \( O(bm) \) for recursion stack.

Greedy Strategy & Job Sequencing

A greedy strategy provides an optimal solution only if the problem exhibits Optimal Substructure and the Greedy Choice Property (meaning a sequence of locally optimal choices leads to a globally optimal solution).

Algorithm JobSequencing(Jobs)
  1. Sort Jobs in descending order of profit.
  2. Initialize an array slots[] to keep track of free time slots.
  3. For each Job i from 1 to N:
        Find a free slot from min(deadline(i), N) down to 1
        If slot is found, assign Job i to that slot.

Time Complexity: Sorting takes \( O(n \log n) \). Placing jobs takes \( O(n^2) \) in worst case. Total = \( O(n^2) \). (Can be optimized to \( O(n \log n) \) using Disjoint Sets).

Q105 marks
Extended Euclidean Algorithm

Why used: It finds the Greatest Common Divisor (GCD) of two integers, but importantly, it also finds the coefficients x and y such that \( ax + by = \gcd(a, b) \). This is crucial in cryptography (like RSA) for calculating Modular Multiplicative Inverses.

function extGCD(a, b)
  if b == 0
      return (a, 1, 0)
  (d, x1, y1) = extGCD(b, a mod b)
  x = y1
  y = x1 - floor(a/b) * y1
  return (d, x, y)

Complexity: \( O(\log(\min(a,b))) \)

Q115 marks
NP-Complete Problems & SAT

NP-Complete: The most difficult problems in NP. If any NP-Complete problem can be solved in polynomial time, then P = NP. (Examples: TSP, Vertex Cover, 3-SAT).

"SAT is NP-complete" (Cook's Theorem Sketch):

  • SAT is in NP because a given truth assignment can be verified in polynomial time.
  • Any problem in NP is solvable by a non-deterministic Turing machine in polynomial time. Cook showed that the execution of any such Turing machine can be encoded as a massive Boolean formula (SAT). Since any NP problem reduces to SAT, SAT is NP-Complete.

Short Notes

(a) Aggregate Analysis

A technique in amortized analysis where we compute the total upper bound \( T(n) \) for a sequence of \( n \) operations. The amortized cost per operation is then simply \( T(n) / n \). It guarantees an average performance over a worst-case sequence.

(b) Selection Problems

The problem of selecting the \( k^{th} \) smallest (or largest) element from an unsorted list. While sorting takes \( O(n \log n) \), selection algorithms (like QuickSelect or Median-of-Medians) can solve this in \( O(n) \) expected or worst-case time.
