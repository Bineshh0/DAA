Complexity & Asymptotic Notations

A. Complexity of an Algorithm

Complexity refers to the theoretical measurement of resources (time and memory space) an algorithm consumes as a function of the input size \( n \). It helps predict scalability.

B. Asymptotic Notations

  • Big Oh \( O(g(n)) \): Defines the asymptotic upper bound (worst-case). \( f(n) \leq c \cdot g(n) \) for all \( n \geq n_0 \).
  • Big Omega \( \Omega(g(n)) \): Defines the asymptotic lower bound (best-case). \( f(n) \geq c \cdot g(n) \) for all \( n \geq n_0 \).
  • Big Theta \( \Theta(g(n)) \): Defines tight bound (average/exact case). \( c_1 g(n) \leq f(n) \leq c_2 g(n) \).
Q210 marks
Divide and Conquer & Randomized Quick Sort

Divide and Conquer: Divide problem into smaller instances, Conquer them recursively, Combine results.

Algorithm RandPartition(A, p, r):
  i = Random(p, r)
  swap(A[i], A[r])
  return Partition(A, p, r) // Standard partition using A[r] as pivot

Algorithm RandQuickSort(A, p, r):
  if p < r:
      q = RandPartition(A, p, r)
      RandQuickSort(A, p, q-1)
      RandQuickSort(A, q+1, r)

Time Complexity: The expected case is \( O(n \log n) \) because the random pivot eliminates the dependency on the input distribution, ensuring perfectly terrible partitions (\( n-1 \) and \( 0 \)) are highly improbable.

Q310 marks
Backtracking vs Recursion & N-Queen Problem

A. Backtracking vs Recursion

Backtracking is an intelligent application of recursion. It uses a "bounding function" to test if the current partial solution can ever lead to a valid final solution. If it cannot, it immediately stops exploring that path (prunes the tree) and "backtracks", whereas standard recursion would exhaustively explore all paths.

B. N-Queen Problem

Place N chess queens on an N×N chessboard so that no two queens threaten each other (no two queens share the same row, column, or diagonal). 
Algorithm NQueens(k, n) // Place kth queen
  For i = 1 to n:
      If Place(k, i) is True: // check bounds
          x[k] = i            // Place queen at row k, col i
          If k == n:
              Print x[1..n]   // Solution found
          Else:
              NQueens(k+1, n) // Recurse to next row

Time Complexity: \( O(n!) \) in worst-case (though drastically pruned compared to pure brute force \( O(n^n) \)).

Selection Sort
Algorithm SelectionSort(A):
  n = length(A)
  for i = 0 to n-2:
      min_idx = i
      for j = i+1 to n-1:
          if A[j] < A[min_idx]:
              min_idx = j
      swap(A[i], A[min_idx])
  • Time Complexity: \( O(n^2) \) in Best, Average, and Worst cases (it always scans the remaining array).
  • Space Complexity: \( O(1) \) (in-place sorting).

Master Method

(a) \( T(n) = 7T(n/2) + n^2 \)

\( a=7, b=2, f(n)=O(n^2) \)

\( n^{\log_b a} = n^{\log_2 7} \approx n^{2.8} \)

Since \( f(n) = n^2 \) is polynomially smaller than \( n^{2.8} \), we are in Case 1.

Complexity: \( \Theta(n^{\log_2 7}) \)

(b) \( T(n) = 4T(n/4) + n \)

\( a=4, b=4, f(n)=O(n) \)

\( n^{\log_b a} = n^{\log_4 4} = n^1 \)

Since \( f(n) = n^1 \) matches \( n^{\log_b a} \), we are in Case 2.

Complexity: \( \Theta(n \log n) \)
Q65 marks
Greedy Algorithm for Fractional Knapsack

The Fractional Knapsack allows items to be broken into smaller pieces. The greedy approach always yields the optimal solution.

Algorithm FractionalKnapsack(items, W):
  Calculate value/weight ratio for all items
  Sort items descending by ratio
  total_value = 0
  For each item in sorted list:
      if W == 0: break
      a = min(item.weight, W)
      total_value = total_value + a * (item.value / item.weight)
      W = W - a
  return total_value

Time Complexity: \( O(n \log n) \) purely due to the sorting step. The iteration takes \( O(n) \).

Q85 marks
Dynamic Programming Elements

DP requires a problem to have two key mathematical elements:

  1. Optimal Substructure: An optimal solution to the overall problem can be constructed from optimal solutions of its subproblems.
  2. Overlapping Subproblems: The recursive algorithm breaks the problem down into the same subproblems over and over. DP solves this by caching answers.
Q95 marks
Vertex Cover Approximation

A greedy approach is to pick an arbitrary edge (u, v), add both vertices to the cover, and remove all incident edges. Repeat until no edges remain.

Why Approximation? Finding the exact minimum cover is NP-Complete. This simple \( O(E) \) algorithm provides an approximation ratio of exactly 2, meaning the cover found will never be larger than twice the size of the true optimal minimum cover.

Q105 marks
Prim's Algorithm for MST

Prim's algorithm builds the Minimum Spanning Tree one vertex at a time by greedily connecting the lowest weight edge originating from the growing MST to an unvisited vertex.

Algorithm Prim(G, start):
  Initialize min-priority queue Q with all vertices
  set key[v] = INFINITY for all v, key[start] = 0
  while Q is not empty:
      u = ExtractMin(Q)
      for each neighbor v of u:
          if v is in Q and weight(u,v) < key[v]:
              parent[v] = u
              key[v] = weight(u,v)

Time Complexity: \( O(E \log V) \) using a Min-Heap (or \( O(E + V \log V) \) with a Fibonacci Heap).

Q115 marks
Classes P, NP, NP-Complete
  • P: Solvable in polynomial time. Example: Matrix Multiplication.
  • NP: Verifiable in polynomial time. Example: Subset Sum.
  • NP-Complete: The hardest problems in NP. If one is solved in polynomial time, all are (P=NP). Example: 3-SAT, TSP.
Q125 marks
Short Notes

(a) Backtracking Strategy

Depth-First Search (DFS) combined with bounding functions. It builds solutions incrementally and abandons paths when they violate conditions, saving massive computation time compared to brute force.

(b) Tractable and Intractable Problem

Tractable: Solvable in practical time (Polynomial). Intractable: Technically solvable, but algorithms run in Exponential Time, making them practically unsolvable for large inputs.
