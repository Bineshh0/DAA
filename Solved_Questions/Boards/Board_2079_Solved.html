Divide & Conquer and Median-of-Medians Selection

A. Divide and Conquer Strategy

A recursive problem-solving paradigm that breaks a problem into smaller subproblems, solves them, and combines their solutions. It has three steps:

  1. Divide: Break the problem into \( k \) smaller, independent subproblems.
  2. Conquer: Solve the subproblems recursively. If they are small enough, solve them as base cases.
  3. Combine: Merge the solutions of the subproblems into the solution for the original problem.

B. Worst-Case Linear Time Selection (Median-of-Medians)

The standard QuickSelect algorithm has a worst-case time complexity of \( O(n^2) \) if the pivot is chosen poorly. The Median-of-Medians algorithm guarantees a good pivot, achieving an \( O(n) \) worst-case time complexity. 
Algorithm Select(A, k):
1. Divide the n elements into groups of 5.
2. Find the median of each group (using insertion sort).
3. Recursively call Select() on the array of n/5 medians to find the "median of medians" (M).
4. Partition array A around the pivot M. Let M end up at index q. Let rank = q - left + 1.
5. If k == rank: return M
   If k < rank: return Select(A[left..q-1], k)
   If k > rank: return Select(A[q+1..right], k - rank)

Complexity Analysis

The recurrence relation is: \( T(n) \leq T(n/5) + T(7n/10) + O(n) \)

This is because finding the median of medians takes \( T(n/5) \). The chosen pivot guarantees that at least \( 3/10 \) of the elements are smaller/larger than it, meaning the maximum size of the recursive partition call is \( 7n/10 \). Solving this recurrence yields \( O(n) \).

Matrix Chain Multiplication (ABCD)

A. DP Algorithm for Matrix Chain Multiplication

Algorithm MatrixChainOrder(p):
  n = length(p) - 1
  Let M[1..n, 1..n] and S[1..n, 1..n] be new tables
  For i = 1 to n: M[i, i] = 0
  For L = 2 to n: // chain length
      For i = 1 to n - L + 1:
          j = i + L - 1
          M[i, j] = INFINITY
          For k = i to j - 1:
              q = M[i, k] + M[k+1, j] + p[i-1]*p[k]*p[j]
              if q < M[i, j]:
                  M[i, j] = q
                  S[i, j] = k
  return M and S

B. Solve for ABCD (A:5x10, B:10x5, C:5x20, D:20x30)

Dimension array \( P = [5, 10, 5, 20, 30] \)

Chain Length L=2:

\( M[1,2] = A \times B = 5 \times 10 \times 5 = 250 \)

\( M[2,3] = B \times C = 10 \times 5 \times 20 = 1000 \)

\( M[3,4] = C \times D = 5 \times 20 \times 30 = 3000 \)

Chain Length L=3:

\( M[1,3] = \min(M[1,1]+M[2,3]+P_0P_1P_3, M[1,2]+M[3,3]+P_0P_2P_3) \)

\( = \min(0 + 1000 + 5 \cdot 10 \cdot 20,\ 250 + 0 + 5 \cdot 5 \cdot 20) \)

\( = \min(1000 + 1000, 250 + 500) = \min(2000, 750) = 750 \) (Split at k=2)

\( M[2,4] = \min(M[2,2]+M[3,4]+P_1P_2P_4, M[2,3]+M[4,4]+P_1P_3P_4) \)

\( = \min(0 + 3000 + 10 \cdot 5 \cdot 30,\ 1000 + 0 + 10 \cdot 20 \cdot 30) \)

\( = \min(3000 + 1500, 1000 + 6000) = \min(4500, 7000) = 4500 \) (Split at k=2)

Chain Length L=4 (Final Answer M[1,4]):

\( M[1,4] = \min \begin{cases} k=1: M[1,1] + M[2,4] + P_0P_1P_4 = 0 + 4500 + (5 \times 10 \times 30) = 4500 + 1500 = 6000 \\ k=2: M[1,2] + M[3,4] + P_0P_2P_4 = 250 + 3000 + (5 \times 5 \times 30) = 3250 + 750 = 4000 \\ k=3: M[1,3] + M[4,4] + P_0P_3P_4 = 750 + 0 + (5 \times 20 \times 30) = 750 + 3000 = 3750 \end{cases} \)

Minimum is 3750, occurring at \( k=3 \).

Backtracking 0-1 Knapsack

A. What is Backtracking?

An algorithmic technique that explores the state-space tree depth-first. It builds solutions incrementally and abandons (backtracks) paths that violate constraints or cannot possibly yield an optimal solution, using a bounding function. This makes it faster than brute-force.

B. 0-1 Knapsack Trace (W=10)

Items: \( w_1=2(p_1=3), w_2=3(p_2=5), w_3=4(p_3=6), w_4=5(p_4=10) \)

Step 1: Calculate Profit/Weight density and sort descending (for bounding function).

10/5=2.0 (I4), 5/3=1.66 (I2), 3/2=1.5 (I1), 6/4=1.5 (I3).

Sorted Order: I4(5kg,$10), I2(3kg,$5), I1(2kg,$3), I3(4kg,$6).

Step 2: Build State-Space Tree with capacity W=10.

  • Take I4 (wt=5, p=10). Remaining cap=5.
  • Take I2 (wt=5+3=8, p=15). Remaining cap=2.
  • Take I1 (wt=8+2=10, p=18). Remaining cap=0.
  • Cannot take I3 (wt=10+4=14 > 10). Backtrack.
  • Exclude I1. Take I3? (wt=8+4=12 > 10). Backtrack.
  • Exclude I2. Take I1 (wt=5+2=7, p=13). Take I3 (wt=7+4=11 > 10). Backtrack.

Through systematic exploration, the max profit path is including I4, I2, and I1.

Iterative GCD Algorithm (Euclidean)
Algorithm IterativeGCD(a, b):
  while b ≠ 0
      temp = b
      b = a mod b
      a = temp
  return a

Time Complexity: \( O(\log(\min(a,b))) \). In the worst case (Fibonacci numbers), the remainder reduces by at least half every two steps.

Tractable vs Intractable & Vertex Cover
  • Tractable Problem: A problem that can be solved by a polynomial-time algorithm (e.g., \( O(n), O(n \log n), O(n^2) \)). Belong to Class P. Example: Sorting.
  • Intractable Problem: A problem for which no polynomial-time algorithm exists (they require exponential time \( O(2^n), O(n!) \)). Belong to NP-Complete/NP-Hard.

Vertex Cover Problem: Given a graph G, find the minimum number of vertices such that every edge in the graph is connected to at least one of these vertices. Finding the exact minimum is intractable (NP-Complete).

Q85 marks
Short Notes

(a) Best, Worst, and Average Case

  • Best Case (\( \Omega \)): Minimum time required for the most favorable input (e.g., Insertion Sort on sorted array).
  • Worst Case (O): Maximum time required for the most unfavorable input (e.g., Quick Sort on sorted array).
  • Average Case (\( \Theta \)): Expected time calculated over all possible inputs assuming uniform distribution.

(b) Greedy Strategy

An algorithmic paradigm that builds up a solution piece by piece, always choosing the next piece that offers the most immediate (local) benefit. Used in Kruskal's, Prim's, Dijkstra's, and Fractional Knapsack.

Kruskal's Algorithm for MST
⚠️ Note: Graph missing from transcript. Standard Algorithm logic provided below.
Algorithm Kruskal(G):
  A = empty set (will hold MST edges)
  Sort edges of G in ascending order by weight
  For each vertex v in G: Make-Set(v)
  
  For each edge (u, v) in sorted order:
      if Find-Set(u) != Find-Set(v):  // no cycle formed
          A = A U {(u, v)}
          Union(u, v)
  return A

Concept: Greedily picks the smallest weight edge across the entire graph that does not form a cycle. Uses Disjoint Set (Union-Find) data structure to detect cycles.

Trace Quick Sort & Complexity

Array: {15, 7, 5, 2, 13, 4, 25}. Pivot = 25 (last element).

1. Compare all to 25. All elements (15,7,5,2,13,4) are < 25. Pivot 25 swaps with itself. Left partition: {15, 7, 5, 2, 13, 4}. Right: Empty.

2. Partition {15, 7, 5, 2, 13, 4}. Pivot = 4. Only 2 is < 4. Swap 15 and 2. Array: {2, 7, 5, 15, 13, 4}. Swap 7 and 4. New: {2, 4, 5, 15, 13, 7}.

3. Partition {5, 15, 13, 7}. Pivot = 7. 5 < 7. Swap 15 and 7. New: {5, 7, 13, 15}.

4. Array fully sorted: {2, 4, 5, 7, 13, 15, 25}.

  • Best Case Complexity: \( O(n \log n) \) (Pivot divides array in equal halves)
  • Worst Case Complexity: \( O(n^2) \) (Pivot is always largest/smallest, creating heavily unbalanced 0 and n-1 partitions).
