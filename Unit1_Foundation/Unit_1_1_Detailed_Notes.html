📘 Unit 1 — Foundation of Algorithm Analysis

CSC 314 · 4 Hrs · Detailed Notes

1.1.1 What is an Algorithm?

An algorithm is a finite, ordered sequence of unambiguous, executable instructions that takes some input and produces the desired output in a finite amount of time.

Five elementary properties (Knuth)

  1. Input — zero or more externally supplied quantities.
  2. Output — at least one quantity produced that satisfies the problem specification.
  3. Definiteness — each instruction is clear, precise, and unambiguous.
  4. Finiteness — terminates after a finite number of steps for every legal input.
  5. Effectiveness — every operation must be basic enough to be executed exactly, in principle by a person with paper and pencil, in finite time.

Why we need algorithms (and their analysis)

  • Solve problems systematically and reproducibly.
  • Predict resource usage (time/space) before implementation.
  • Compare two approaches independent of hardware, OS, or programming language.
  • Identify bottlenecks and prove correctness/termination.

1.1.2 The RAM Model

The Random Access Machine (RAM) is a theoretical computation model used for analyzing algorithms. Assumptions:
  • Memory consists of an unbounded sequence of cells, each holding an integer or real number.
  • Any memory cell can be accessed in $O(1)$ (constant) time — "random access".
  • Each primitive operation — arithmetic (+, −, ×, ÷, mod), comparison (<, =, >), assignment, array indexing, function call/return — costs $O(1)$.
  • No concurrency, no cache hierarchy, no I/O delay.

Time complexity is therefore obtained by counting the number of primitive operations executed, not measuring seconds. A loop that runs $n$ times contributes $\Theta(n)$ operations regardless of which computer runs it.

1.1.3 Time & Space Complexity

Time complexity $T(n)$: number of primitive operations performed as a function of input size $n$.
Space complexity $S(n)$: amount of memory cells used (input + auxiliary).

Best / Worst / Average case

CaseSymbolMeaningLinear Search Example
Best$\Omega$Minimum operations over all inputs of size $n$$O(1)$ — key at index 0
Worst$O$Maximum operations — used for guarantees$O(n)$ — key absent / at end
Average$\Theta$Expected operations over a probability distribution of inputs$O(n)$ — average n/2 probes

Worked example — Iterative Factorial (a typical line-by-line RAM analysis)

Algorithm Factorial(n): 1. fact ← 1 // cost c₁, executed 1 time 2. for i = 1 to n do // cost c₂, executed (n+1) times 3. fact ← fact × i // cost c₃, executed n times 4. return fact // cost c₄, executed 1 time

Total cost: $T(n)=c_1+c_2(n+1)+c_3 n+c_4 = (c_2+c_3)n+(c_1+c_2+c_4) = \Theta(n)$.

Space: only the variables fact and i → $S(n)=\Theta(1)$.

The recursive version fact(n)=n·fact(n-1) also runs in $\Theta(n)$ time but uses $\Theta(n)$ stack space (one frame per call).

1.1.4 Aggregate Analysis

Aggregate analysis shows that the total cost of any sequence of $n$ operations is at most $T(n)$, hence the amortized (average) cost per operation is $T(n)/n$ — even if a few individual operations are expensive.

Classic example — incrementing a binary counter from 0 to $n$

  • Bit 0 flips on every increment → $n$ flips.
  • Bit 1 flips every 2 increments → $n/2$ flips.
  • Bit $k$ flips $n/2^k$ times.

Total flips $=\sum_{k=0}^{\lfloor\log n\rfloor} n/2^k < 2n = O(n)$. Therefore amortized cost per INCREMENT $=O(n)/n = O(1)$, although a single increment can flip up to $\log n$ bits in the worst case.

1.2 Asymptotic Notations

Asymptotic notations describe the growth rate of $T(n)$ for large $n$, ignoring constant factors and lower-order terms.

↑ T(n) | c·g(n) ← Big-O ceiling | ╱───────── | ╱ f(n) | ╱ ╱ | ╱ ╱ c'·g(n) ← Big-Ω floor |____╱_╱_______________→ n n₀

Examples

  • $3n^2+5n+7$ : pick $c=4, n_0=10$ → $3n^2+5n+7\le 4n^2$ → $=O(n^2)$.
  • Same function: pick $c=3$ → $3n^2 \le 3n^2+5n+7$ → $=\Omega(n^2)$.
  • Both hold simultaneously → $=\Theta(n^2)$.
  • $n\log n = O(n^2)$ but $\ne \Theta(n^2)$ because lower bound fails.
  • $2^n \ne O(n^k)$ for any constant $k$ (exponential always beats polynomial).
Properties: transitivity, reflexivity (in $O$/$\Omega$/$\Theta$), symmetry ($\Theta$ only), and transpose symmetry: $f=O(g)\iff g=\Omega(f)$.

1.3 Recurrences & Recursive Algorithms

A recurrence relation expresses $T(n)$ — the cost of solving an input of size $n$ — in terms of the cost on one or more smaller inputs. Recursive algorithms always produce recurrences.

The general divide-and-conquer form is:

T(n) = a · T(n/b) + f(n) ,   a ≥ 1, b > 1

where a = number of recursive sub-calls, b = factor by which input shrinks, f(n) = work to divide and combine.

Method 1 — Substitution (guess + induction)

Steps: (1) guess the form of the solution; (2) verify by mathematical induction; (3) solve for unknown constants.

Example: $T(n)=2T(n/2)+1,\;T(1)=1$. Prove $T(n)=O(n)$.

Guess : T(n) ≤ c·n − 1 (subtract 1 to absorb the +1 term) Base : T(1)=1 ≤ c·1 − 1 ⟹ c ≥ 2 ✓ IH : T(n/2) ≤ c·(n/2) − 1 Inductive : T(n) = 2T(n/2)+1 ≤ 2[c(n/2) − 1] + 1 = cn − 2 + 1 = cn − 1 ✓ ∴ T(n) = O(n)

Method 2 — Recursion Tree

Draw the recursion as a tree: each node = one sub-problem with its non-recursive cost $f(\cdot)$. Sum the costs level-by-level, then over all levels.

Example: $T(n)=2T(n/2)+n$ (Merge-Sort recurrence)

Level nodes cost per node level total 0 1 n n 1 2 n/2 n 2 4 n/4 n … … … … k 2^k n/2^k n Depth d = log₂ n (sub-problem reaches size 1). Total cost = n × (depth+1) = n(log n + 1) = Θ(n log n)

Example: $T(n)=3T(n/4)+cn^2$

Level 0 : cost = cn² Level 1 : 3 · c(n/4)² = (3/16)·cn² Level 2 : 9 · c(n/16)² = (3/16)²·cn² ⋮ Geometric series with ratio 3/16 < 1 ⟹ sum converges T(n) = cn² · Σ(3/16)^i = Θ(n²)

Method 3 — Master Theorem (shortcut for $T(n)=aT(n/b)+f(n)$)

Compute the "watershed" $n^{\log_b a}$ and compare it with $f(n)$:

CaseCondition on $f(n)$ vs $n^{\log_b a}$Result
1 (heavy leaves)$f(n)=O(n^{\log_b a-\epsilon})$ for some $\epsilon>0$$T(n)=\Theta(n^{\log_b a})$
2 (balanced)$f(n)=\Theta(n^{\log_b a})$$T(n)=\Theta(n^{\log_b a}\log n)$
3 (heavy root)$f(n)=\Omega(n^{\log_b a+\epsilon})$ + regularity $af(n/b)\le cf(n)$$T(n)=\Theta(f(n))$

Walk-through examples (covering every pattern you may see)

① T(n) = 2T(n/2) + n a=2,b=2 → n^1 = f ⟹ Case 2 ⟹ Θ(n log n) [Merge Sort] ② T(n) = 2T(n/2) + n² n^1 vs n² ⟹ Case 3 ⟹ Θ(n²) ③ T(n) = 2T(n/2) + 1 n^1 vs 1 ⟹ Case 1 ⟹ Θ(n) ④ T(n) = 3T(n/2) + n n^{log₂3}≈n^{1.58} > n ⟹ Case 1 ⟹ Θ(n^{log₂3}) ⑤ T(n) = 2T(n/4) + √n n^{log₄2}=n^{0.5}=√n=f ⟹ Case 2 ⟹ Θ(√n log n) ⑥ T(n) = 4T(n/4) + n n^1 = f ⟹ Case 2 ⟹ Θ(n log n) ⑦ T(n) = 7T(n/2) + n² n^{log₂7}≈n^{2.81} > n² ⟹ Case 1 ⟹ Θ(n^{log₂7}) ⑧ T(n) = 9T(n/3) + n n² > n ⟹ Case 1 ⟹ Θ(n²) ⑨ T(n) = 2T(n/4) + n² n^{0.5} vs n² ⟹ Case 3 ⟹ Θ(n²) ⑩ T(n) = 5T(n/4) + kn n^{log₄5}≈n^{1.16} > n ⟹ Case 1 ⟹ Θ(n^{log₄5})
⚠ When Master Theorem fails: when $f(n)$ lies between two cases (e.g. $T(n)=2T(n/2)+n\log n$ — $f=n\log n$ is larger than $n$ but not polynomially larger). Use the recursion-tree method or the Akra–Bazzi method instead. For the gap example the tree gives $\Theta(n\log^2 n)$.
Take-away: After Unit 1 you should be able to (a) state the 5 properties of an algorithm, (b) explain the RAM model, (c) derive $T(n)$ from pseudocode by counting primitive operations, (d) prove a function is $O$/$\Omega$/$\Theta$ by finding $c$ and $n_0$, (e) solve any divide-and-conquer recurrence using substitution, recursion-tree, or Master Theorem, and (f) explain aggregate analysis with the binary-counter example.
