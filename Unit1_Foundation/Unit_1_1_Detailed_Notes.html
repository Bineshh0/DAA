1.1 How is Time Complexity Actually Obtained?

Time Complexity is not calculated in "seconds" because hardware varies (a supercomputer is faster than a phone). Instead, it is obtained by counting the exact number of basic primitive operations (assignment, comparison, arithmetic) that a processor must execute relative to an input size $N$.

According to the RAM Model, every single primitive operation takes exactly $O(1)$ constant time limit. To derive the time complexity of any algorithm, we meticulously sum the mathematical operations.

Example Derivation: Nested Loops Analysis

Let's find the exact time complexity of the following code snippet:

Algorithm MatrixSum(A, N): 1. sum = 0 // Cost: c1, Times Executed: 1 2. for i = 1 to N do // Cost: c2, Times Executed: N+1 3. for j = 1 to N do // Cost: c3, Times Executed: N(N+1) 4. sum = sum + A[i][j] // Cost: c4, Times Executed: N * N 5. return sum // Cost: c5, Times Executed: 1

Mathematical Derivation of the Sum:

  1. Line 1: Assignment operation executes exactly once. -> $c_1 \times 1$
  2. Line 2: The outer loop runs $N$ times successfully, plus $1$ final time where the condition fails. -> $c_2 \times (N+1)$
  3. Line 3: The inner loop executes successfully $N$ times for every single iteration of the outer loop. PLUS, it fails exactly 1 time per outer loop. So it executes $N \times (N+1)$ total times. -> $c_3 \times (N^2 + N)$
  4. Line 4: The core addition and array access executes exactly $N \times N$ times safely. -> $c_4 \times N^2$
  5. Line 5: Return runs exactly once. -> $c_5 \times 1$
Total Time T(N) = c1 + c2(N+1) + c3(N^2 + N) + c4(N^2) + c5
T(N) = (c3 + c4)N^2 + (c2 + c3)N + (c1 + c2 + c5)

Because asymptotic analysis ignores constant fractions ($c_i$) and explicitly drops the lower-order growth limits (like the independent $N$ and the constants), we strictly keep the most dominant term. Because the dominant mathematical expression is strictly $N^2$, we scientifically derive the time bound as:

Result: $T(N) = O(N^2)$

1.2 Solving Recurrence Relations

When algorithms use Recursion (like Merge Sort or Binary Search), they do not use `for` loops. We cannot just "count" loop iterations. We must solve a Recurrence Relation — a mathematical equation natively defining the algorithm operation sequence in terms of itself.

General form: $T(N) = aT(N/b) + f(N)$, where a is the physical number of recursive calls, b is the input shrinkage division variable, and f(N) is the computational cost of dividing/merging outside the recursive mechanism.

Method 1: The Substitution Method (Mathematical Induction)

The Substitution methodology forces us to mathematically guess the bound structure, and subsequently use Mathematical Induction to rigorously prove our guess is definitively correct.

Example Objective: Solve the recurrence $T(N) = 2T(N/2) + N$ (The Merge Sort recurrence).

Step 1: Make a Guess. We suspect the bound limit converges at $O(N \log N)$. So our formal assumption is: $T(N) \le C \cdot N \log N$ for some constant $C > 0$.

Step 2: Proof via Induction Trace.

Assume the limit property identically applies to the smaller constraint sub-problem $T(N/2)$: So, $T(N/2) \le C \cdot (\frac{N}{2}) \log(\frac{N}{2})$ We precisely substitute this assumption directly back into the originating general recurrence: $T(N) = 2 \cdot T(N/2) + N$ $T(N) \le 2 \cdot [C \cdot (\frac{N}{2}) \log(\frac{N}{2})] + N$ Execute Algebraic Expansion natively: $T(N) \le C \cdot N \log(\frac{N}{2}) + N$ Using strictly logarithm properties ($\log(A/B) = \log A - \log B$): $T(N) \le C \cdot N \cdot (\log N - \log 2) + N$ Since $\log_2 2 = 1$: $T(N) \le C \cdot N \log N - C \cdot N + N$ $T(N) \le C \cdot N \log N - N(C - 1)$

Step 3: Verification. To strictly prove $T(N) \le C \cdot N \log N$, the residual remainder polynomial $-N(C-1)$ must mathematically be $\le 0$. This rigorously holds true arbitrarily whenever we select $C \ge 1$. Therefore, our mathematical hypothesis is flawless.

Final Concluded Bound: $T(N) = O(N \log N)$

Method 2: The Recursion Tree Method

The Recursion Tree strategy maps out the explicit recursive hierarchy structurally as a visual tree graph. We accurately track the computational $f(N)$ cost globally across every single horizontal tree level, and mathematically execute an absolute geometric summation $\Sigma$ aggregating all dimensional levels to precisely calculate $T(N)$.

Example Objective: Solve the unequal recurrence $T(N) = 3T(N/4) + C \cdot N^2$.

Step 1: Draw the Branching Structure.

Level 0: The root cost is naturally $C \cdot N^2$. It physically branches into exactly 3 divergent nodes, each processing subset dimensions of $N/4$. Level 1: The 3 descendant nodes structurally cost: Node 1: $C \cdot (\frac{N}{4})^2 = C \cdot \frac{N^2}{16}$ Node 2: $C \cdot (\frac{N}{4})^2 = C \cdot \frac{N^2}{16}$ Node 3: $C \cdot (\frac{N}{4})^2 = C \cdot \frac{N^2}{16}$ => Aggregated Level 1 Cost = $3 \times (C \cdot \frac{N^2}{16}) = \frac{3}{16} C \cdot N^2$ Level 2: The 3 nodes exponentially shatter into 9 sub-nodes total. Subset dimensions shrink identically to $(N/16)$. Cost natively per secondary sub-node: $C \cdot (\frac{N}{16})^2 = C \cdot \frac{N^2}{256}$ => Aggregated Level 2 Cost = $9 \times (C \cdot \frac{N^2}{256}) = \frac{9}{256} C \cdot N^2 = (\frac{3}{16})^2 C \cdot N^2$

Step 2: Geometrically Sum the Structural Hierarchy.

$T(N) = (\text{Cost Level 0}) + (\text{Cost Level 1}) + (\text{Cost Level 2}) + \dots + (\text{Cost Level } d)$

$T(N) = C \cdot N^2 + \frac{3}{16} C \cdot N^2 + (\frac{3}{16})^2 C \cdot N^2 + \dots$

We factor precisely out the identical $C \cdot N^2$ root matrix:
$T(N) = C \cdot N^2 \cdot \sum_{i=0}^{d} (\frac{3}{16})^i$

Step 3: Limits Convergence Verification. Because the geometric scalar integer $(3/16)$ is emphatically less than $1$, the infinite polynomial summation rigorously converges universally forcing a restricted constant $K$. Thus $T(N) = K \cdot C \cdot N^2$.

Final Concluded Bound: $T(N) = \Theta(N^2)$

Method 3: The Master Theorem

Provides a direct shortcut for recurrences exactly formatted as: $T(n) = a \cdot T(n/b) + f(n)$

⚠️ Exam Strategy: Natively calculate the logarithmic branch boundary: $n^{\log_b a}$. Then explicitly compare this polynomial weight against the merging cost $f(n)$!
Master Theorem ConditionsMathematical MeaningExact Complexity Result
Case 1: Heavy Leaves
$f(n) = O(n^{\log_b a - \epsilon})$		 The branching $n^{\log_b a}$ is substantially much larger natively than $f(n)$. The root merge cost is useless. Leaves dominate absolute computation. $T(n) = \Theta(n^{\log_b a})$
Case 2: Exact Balance
$f(n) = \Theta(n^{\log_b a})$		 The branch recursion generation cost and the external merge algorithm cost scale beautifully exactly at the exact same bound scalar limits. $T(n) = \Theta(n^{\log_b a} \cdot \log n)$
Case 3: Heavy Root
$f(n) = \Omega(n^{\log_b a + \epsilon})$		 The external merge calculation limits mathematically dominate. Generating the recursion tree limits is effectively free compared to it. $T(n) = \Theta(f(n))$

Examples of Mathematical Master Execution:

Example 1: $T(N) = 9T(N/3) + N$

  • Identify parameters: $a=9, b=3, f(N)=N^1$.
  • Execute weight bound logic: $N^{\log_3 9} = N^2$.
  • Compare exactly $N^1$ against $N^2$. Since $N^1 < N^2$, Case 1 universally triggers.
  • Result limit = $\Theta(N^2)$.

Example 2: $T(N) = 2T(N/2) + N \log N$

  • Identify parameters: $a=2, b=2, f(N)=N \log N$.
  • Execute weight bound logic: $N^{\log_2 2} = N^1$.
  • Compare exactly $N \log N$ against $N^1$. It is NOT identically equal (fails Case 2), and NOT polynomially larger (fails Case 3 strict $\epsilon$ requirement constraint).
  • WARNING: The Master Theorem mathematically fails here! You must strictly use the Recursion Tree or Advanced Akra-Bazzi method to natively resolve this!
