1.1 Algorithm & Its Properties

Algorithm: A finite, ordered sequence of unambiguous, executable instructions that transforms a given input into the desired output in a finite amount of time.

Five Elementary Properties (Knuth)

  1. Input: Zero or more well-defined inputs.
  2. Output: At least one output that satisfies the problem.
  3. Definiteness: Each step must be precise and unambiguous.
  4. Finiteness: Must terminate after a finite number of steps.
  5. Effectiveness: Every operation must be basic enough to be performed exactly in finite time using pencil and paper.

Why Do We Need Algorithms / Analysis?

  • Predict resource usage (time, space) before coding.
  • Compare two algorithms independent of hardware/language.
  • Identify bottlenecks and choose the best approach for given input size.
  • Prove correctness and termination.

1.2 RAM Model (Random Access Machine)

A theoretical machine where every primitive operation (arithmetic +,-,*,/, comparison, assignment, array index, function call/return) costs exactly $O(1)$ time. Memory access is also $O(1)$ (random access). There is no concurrency, no memory hierarchy, no cache effects.

Worked Example: Factorial Algorithm (Iterative)

Algorithm Factorial(n): 1. fact = 1 // c1, 1 time 2. for i = 1 to n do // c2, (n+1) times 3. fact = fact * i // c3, n times 4. return fact // c4, 1 time

Total: $T(n)=c_1+c_2(n+1)+c_3 n+c_4 = (c_2+c_3)n+(c_1+c_2+c_4)$.

Result: $T(n)=\Theta(n)$, Space $=\Theta(1)$ (only fact, i).

1.4 Aggregate Analysis

Aggregate Analysis shows that the total cost of a sequence of $n$ operations is $T(n)$, so the amortized cost per operation is $T(n)/n$ — even if some individual operations are expensive.

Classic example: Incrementing a binary counter from 0 to n.

  • Bit 0 flips every increment → n times
  • Bit 1 flips every 2 increments → n/2 times
  • Bit k flips n/$2^k$ times
  • Total flips $= \sum_{k=0}^{\lfloor \log n\rfloor} n/2^k < 2n = O(n)$
  • Amortized cost per INCREMENT $= O(n)/n = O(1)$.

  • $3n^2+5n+7 = O(n^2)$ — pick $c=4, n_0=10$.

1.6 Recurrences: Recursive Algorithms & Recurrence Relations

A recurrence expresses $T(n)$ in terms of $T$ on smaller inputs. General divide-and-conquer form: $T(n)=aT(n/b)+f(n)$.

(a) Substitution Method (Guess + Induction)

Board 2080 Q1: Prove $T(n)=2T(n/2)+1$ is $O(n)$.

Guess: T(n) ≤ c·n − 1 Base: T(1)=1 ≤ c·1 − 1 ⟹ c ≥ 2 ✓ Inductive step: assume T(n/2) ≤ c(n/2) − 1 T(n) = 2T(n/2)+1 ≤ 2[c(n/2)−1]+1 = cn − 2 + 1 = cn − 1 ✓ Therefore T(n) = O(n).

(b) Recursion-Tree Method

Board 2078 Q4: Solve $T(n)=2T(n/2)+1$ by recursion tree.

Level 0: 1 cost = 1 Level 1: 1 1 cost = 2 Level 2: 1 1 1 1 cost = 4 ... Level k: 2^k nodes each cost 1 cost = 2^k Depth d = log₂ n (when subproblem = 1) Leaves at depth d: 2^d = n → cost = n Total = 1 + 2 + 4 + … + n = 2n − 1 = O(n)

(c) Master Theorem

For $T(n)=aT(n/b)+f(n)$ with $a\ge 1, b>1$, compare $f(n)$ with $n^{\log_b a}$:

CaseConditionResult
1$f(n)=O(n^{\log_b a-\epsilon})$ for some $\epsilon>0$$T(n)=\Theta(n^{\log_b a})$
2$f(n)=\Theta(n^{\log_b a})$$T(n)=\Theta(n^{\log_b a}\log n)$
3$f(n)=\Omega(n^{\log_b a+\epsilon})$ + regularity$T(n)=\Theta(f(n))$
