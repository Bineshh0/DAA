Q1. Heap Sort (Max-Heapify, Build-Max-Heap) + Analysis + Example [6+4 = 10]

Definition

Heap Sort is a comparison-based, in-place sorting algorithm that uses a binary max-heap data structure. It first builds a max-heap from the array, then repeatedly extracts the maximum element to produce a sorted array.

Module 1: Max-Heapify(A, i)

Maintains the max-heap property at node i. Assumes left and right subtrees are already max-heaps but A[i] may violate the property.

MAX-HEAPIFY(A, i):
    l = LEFT(i)
    r = RIGHT(i)
    largest = i
    if l ≤ heap-size[A] and A[l] > A[largest]
        largest = l
    if r ≤ heap-size[A] and A[r] > A[largest]
        largest = r
    if largest ≠ i
        swap A[i] ↔ A[largest]
        MAX-HEAPIFY(A, largest)  // recurse down

Time Complexity: O(log n) — proportional to the height of the heap.

Module 2: Build-Max-Heap(A)

Converts an unordered array into a max-heap by calling Max-Heapify bottom-up on all internal (non-leaf) nodes.

BUILD-MAX-HEAP(A):
    heap-size[A] = length[A]
    for i = ⌊length[A]/2⌋ downto 1
        MAX-HEAPIFY(A, i)

Time Complexity: O(n) — tighter analysis shows it is linear, not O(n log n).

Module 3: Heap-Sort(A)

HEAP-SORT(A):
    BUILD-MAX-HEAP(A)
    for i = length[A] downto 2
        swap A[1] ↔ A[i]       // move max to sorted end
        heap-size[A] = heap-size[A] - 1
        MAX-HEAPIFY(A, 1)   // restore heap

Overall Time Complexity: O(n log n) — Build is O(n) + n-1 calls to Max-Heapify each O(log n).

Example: A = [4, 1, 3, 2, 16, 9]

Step 1 — Build-Max-Heap:
Start from i = 3 (⌊6/2⌋) down to 1, calling Max-Heapify:
• Heapify(A, 3): A[3]=3, children: 9. Swap 3↔9 → [4, 1, 9, 2, 16, 3]
• Heapify(A, 2): A[2]=1, children: 2, 16. Swap 1↔16 → [4, 16, 9, 2, 1, 3]
• Heapify(A, 1): A[1]=4, children: 16, 9. Swap 4↔16 → [16, 4, 9, 2, 1, 3]. Then recurse: swap 4↔2? No. → [16, 4, 9, 2, 1, 3]
Max-Heap: [16, 4, 9, 2, 1, 3]

Step 2 — Extract & Sort:
• Swap 16↔3 → [3, 4, 9, 2, 1 | 16]. Heapify → [9, 4, 3, 2, 1]
• Swap 9↔1 → [1, 4, 3, 2 | 9, 16]. Heapify → [4, 2, 3, 1]
• Continue... → Final sorted array: [1, 2, 3, 4, 9, 16]

Q2. Asymptotic Notation (Geometrical Interpretation + Inequality) and Merge Sort [4+4+2 = 10]

Asymptotic Notations

Asymptotic notations describe the growth rate of an algorithm's running time as input size n → ∞.

NotationNameInequalityGeometric Meaning
O (Big-O) Upper Bound 0 ≤ f(n) ≤ c·g(n), ∀ n ≥ n₀ f(n) curve lies on or below c·g(n) after n₀. The c·g(n) line acts as a ceiling.
Ω (Big-Omega) Lower Bound 0 ≤ c·g(n) ≤ f(n), ∀ n ≥ n₀ f(n) curve lies on or above c·g(n) after n₀. The c·g(n) line acts as a floor.
Θ (Big-Theta) Tight Bound 0 ≤ c₁·g(n) ≤ f(n) ≤ c₂·g(n), ∀ n ≥ n₀ f(n) is sandwiched between two curves c₁·g(n) and c₂·g(n) after n₀.

Example: If f(n) = 3n + 2, then f(n) = O(n) with c=4, n₀=2, since 3n+2 ≤ 4n for all n ≥ 2.

Merge Sort — Divide and Conquer

Merge Sort divides the array into two halves, recursively sorts each half, and then merges the two sorted halves.

  • Divide: Split the array into two halves at midpoint.
  • Conquer: Recursively sort both halves.
  • Combine: Merge two sorted halves into one sorted array in O(n) time.

Recurrence: T(n) = 2T(n/2) + Θ(n) → T(n) = O(n log n)

Example: A = [38, 27, 43, 3]

Divide Phase:
[38, 27, 43, 3] → [38, 27] and [43, 3]
[38, 27] → [38] and [27]  |  [43, 3] → [43] and [3]

Merge Phase:
Merge [38],[27] → compare 38 vs 27 → [27, 38]
Merge [43],[3] → compare 43 vs 3 → [3, 43]
Merge [27,38],[3,43] → 3, 27, 38, 43 → [3, 27, 38, 43] ✓

Q3. Define Recurrence Relation and Solve T(n) = 3T(n/4) + n² using Recursion Tree [1+4 = 5]

Definition

A recurrence relation is an equation that describes a function in terms of its value on smaller inputs. It is used to express the running time of recursive algorithms.

Recursion Tree Solution

Each node represents the non-recursive cost at that level. The root does n² work and spawns 3 subproblems of size n/4.

Level 0 (root): 1 node → Cost = n²
Level 1: 3 nodes, each (n/4)² → Cost = 3·(n/4)² = (3/16)·n²
Level 2: 9 nodes, each (n/16)² → Cost = 9·(n/16)² = (3/16)²·n²
Level i: 3ⁱ nodes → Cost = (3/16)ⁱ · n²
Depth: Tree ends when n/4ⁱ = 1, i.e., depth = log₄ n

Total cost: T(n) = n² · Σ (3/16)ⁱ for i = 0 to log₄n

Since 3/16 < 1, this is a decreasing geometric series. It converges to at most 1/(1 − 3/16) = 16/13, a constant.

∴ T(n) = Θ(n²)
The root node dominates the total cost.

Q4. Explain Insertion Sort and Analyze the Complexity [5]

Algorithm

Insertion Sort works like sorting a hand of playing cards. You pick one card at a time and insert it into its correct position among the already-sorted cards on the left.

INSERTION-SORT(A):
    for j = 2 to length[A]
        key = A[j]          // pick the card
        i = j - 1
        while i > 0 and A[i] > key
            A[i+1] = A[i]   // shift larger elements right
            i = i - 1
        A[i+1] = key         // insert in correct position

Complexity Analysis

Best CaseAlready sorted0 times (key is always ≥ A[i])O(n)
Worst CaseReverse sorted1+2+...+(n-1) = n(n-1)/2O(n²)
SpaceIn-place—O(1)

Q5. Explain MST (Kruskal's Algorithm) with Example [5]

Minimum Spanning Tree (MST)

An MST of a connected, weighted, undirected graph is a subset of edges that connects all V vertices with minimum total weight and no cycles. It always has exactly V−1 edges.

Kruskal's Algorithm (Greedy)

  1. Sort all edges by weight in ascending order.
  2. Pick the smallest edge. If adding it does NOT form a cycle (checked via Union-Find / Disjoint Set), include it in the MST.
  3. Repeat until MST has V−1 edges.

Time Complexity: O(E log E) due to sorting edges.

Example

Graph (4 vertices: A, B, C, D):
Edges: A—B=1, A—C=4, B—C=2, B—D=6, C—D=3

Step 1 — Sort edges: A—B(1), B—C(2), C—D(3), A—C(4), B—D(6)

Step 2 — Greedy selection:
• Pick A—B = 1. No cycle. MST = {A—B}. ✓
• Pick B—C = 2. No cycle. MST = {A—B, B—C}. ✓
• Pick C—D = 3. No cycle. MST = {A—B, B—C, C—D}. ✓
• V−1 = 3 edges reached. STOP.

MST Total Weight = 1 + 2 + 3 = 6
(Edges A—C and B—D are discarded.)

Q6. Explain Worst Case Complexity of Quick Sort [3+2 = 5]

Quick Sort Overview

Quick Sort uses Divide and Conquer. It selects a pivot, partitions the array such that elements ≤ pivot go left and elements > pivot go right, then recursively sorts both sides.

When Does Worst Case Occur?

The worst case happens when the partition is maximally unbalanced every time — i.e., the pivot is always the smallest or largest element. This consistently produces one subproblem of size n−1 and another of size 0.

Common trigger: Array is already sorted (or reverse sorted) and we naively pick the first or last element as pivot.

Complexity Derivation

Recurrence:
T(n) = T(n−1) + T(0) + Θ(n)
Since T(0) = Θ(1): T(n) = T(n−1) + Θ(n)

Expanding:
T(n) = Θ(n) + Θ(n−1) + Θ(n−2) + ... + Θ(1)
     = Θ(n + (n−1) + (n−2) + ... + 1)
     = Θ(n(n+1)/2)
Worst Case Time Complexity of Quick Sort = O(n²)

Q7. a. Aggregate Analysis   b. RAM Model [2.5 + 2.5 = 5]

a. Aggregate Analysis

Aggregate Analysis is a method of amortized analysis that determines the average cost per operation over a worst-case sequence of n operations.

  • Instead of analyzing each operation independently, we compute the total cost T(n) for all n operations combined.
  • The amortized cost per operation = T(n) / n.
  • This guarantees the average even in the worst case — it does NOT rely on probability or randomness.

Example: In a dynamic array with doubling, most insertions cost O(1) but occasional resizing costs O(n). Aggregate analysis shows the total cost of n insertions is O(n), so amortized cost per insert = O(1).

b. RAM (Random Access Machine) Model

The RAM model is an abstract computational model used to analyze algorithms independent of actual hardware.

  • Sequential execution: Instructions execute one at a time (no parallelism).
  • Constant-time operations: Simple operations (arithmetic: +, −, ×; comparisons; assignments; array access A[i]) each take exactly 1 time step.
  • Infinite memory: Unlimited memory is available, and each memory access takes 1 step (random access — not sequential).
  • Complex operations like sorting or exponentiation are NOT single steps.

The RAM model allows us to count the number of basic operations as a measure of running time, abstracting away hardware details.
